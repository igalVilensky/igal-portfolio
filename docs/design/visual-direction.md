# Visual Direction

Active direction, 2026-10-10. Read with `docs/strategy/positioning.md`; this supersedes previous SaaS-landing-page and recruiter-snapshot prescriptions. Milestone 1 changes documentation only.

## Foundation

Preserve the current restrained, document-like foundation: narrow readable layouts, clear typography, generous but purposeful whitespace, simple bordered rows, neutral surfaces, quiet dark mode, and modest icons. Existing shared page primitives remain the starting point.

Explore a hybrid of a minimal editorial personal website, a technical engineering journal, and a thoughtfully designed software portfolio. The visual hierarchy should make work and ideas easy to read, with enough personal voice to feel authored.

## Layout and hierarchy

Home should introduce Igal, his current engineering focus, selected work, and a short personal introduction. Link naturally to experiments and, once content exists, notes. Contact can be a quiet text section. This is a future content direction, not a requirement to add a section for every topic.

Avoid a CV-driven homepage, role tags as the main message, recruiter snapshots, repeated hiring CTAs, large statistics grids, and technology badge collections. Keep existing useful compact project metadata where it helps explain the work. A CV may remain a secondary reference; it should not define the reading flow.

Use readable project rows and document-style case studies to explain the problem, contribution, approach, trade-offs, and outcome or limitations. Distinguish professional work from independent work through plain labels and context, without treating small experiments as lesser achievements.

## Visual language

* Preserve the existing neutral palette, restrained accents, type system, and light/dark support; no new fonts or palette migration are prescribed.
* Use comfortable line lengths, clear headings, readable body sizes, and consistent spacing.
* Use screenshots or diagrams only when they explain verified, publicly shareable work. Apply employer confidentiality rules before inclusion.
* Keep motion functional and subtle, respect reduced motion, and never delay reading.
* Preserve keyboard access, visible focus, semantic headings, adequate contrast, descriptive links, mobile readability, and usable tool states.

Avoid generic SaaS landing-page layouts, creative-agency styling, flashy animation, neon/glass effects, decorative AI graphics, stock imagery, oversized promotional panels, and excessive CTAs.

## Personal voice and tools

A short first-person introduction, carefully chosen personal context, and actual engineering observations can provide personality. Do not invent personal material to fill a layout.

Experiments remain interactive. Preserve their inputs, outputs, error/loading states, limitations, and source links. The assistant can become an optional exploration interface with concise sourced answers; its final name and placement are undecided. No chatbot mascot or dominant AI hero is needed.

## Review criteria

A page should be comfortable to read, show meaningful work or ideas, retain accessible mobile interaction, and feel consistent with the Hybrid Personal Engineering Website. New visual treatments must serve content rather than decorate it.
